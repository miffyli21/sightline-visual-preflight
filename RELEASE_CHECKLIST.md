# Public Alpha Release Checklist

## What is ready locally

- [x] MIT license
- [x] Privacy and security note
- [x] Contribution guidance
- [x] Bug and workflow-feedback templates
- [x] Public SVG validation examples
- [x] Five-minute validation protocol
- [x] Initial changelog
- [x] GitHub release title and body
- [x] Xiaohongshu tester-recruitment package

## Before creating a public repository

- [ ] Confirm the exact GitHub account and repository name
- [ ] Confirm that the repository is public
- [ ] Confirm the final README and release copy
- [ ] Confirm that no client, personal, paid, or unlicensed assets are included
- [ ] Confirm the exact Xiaohongshu account and final post package if a post will be published

## First 72 hours after release

- [ ] Respond to reproducible bug reports
- [ ] Separate real workflow feedback from general praise
- [ ] Count successful tests, confusing steps, and requests for new features
- [ ] Avoid adding features before at least one repeated user need appears
- [ ] Record whether the project attracts design-service inquiries as well as tool feedback
