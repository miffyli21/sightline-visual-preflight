## 它能帮你先发现什么

- 海报缩小或进入手机信息流后，小字是否已经看不清；
- 颜色变成灰阶或进入色觉模拟后，状态和重点是否仍能区分；
- 文字压在渐变、阴影或照片上时，实际对比度是否偏低；
- 标题、价格、按钮等必须看清的信息，是否值得交付前再调整一次。

Sightline 不要求你有 Figma 源文件：拿最终导出的图片就能检查。它不替代正式无障碍审计，只负责把容易忽略的视觉风险更早摆到你面前。

## 30 秒开始

1. [打开在线工具](https://miffyli21.github.io/sightline-visual-preflight/?lang=zh)；
2. 先看自带风险示例，或导入自己的 PNG、JPG、WebP、GIF / SVG；
3. 点击“小屏”“灰阶”或不同色觉模拟，再对可疑文字和背景做 A / B 取色。

所有图像处理都发生在当前浏览器中。你也可以下载仓库后双击“打开 Sightline.bat”，完全离线使用。

试过之后如果有一步不好懂，可以直接[提交一条简短反馈](https://github.com/miffyli21/sightline-visual-preflight/issues/new?template=feedback.md)。不需要懂代码。

## 第一版能做什么

- 导入 PNG、JPG、WebP 或 GIF 的第一帧；
- 在原图、小屏、灰阶、红弱、绿弱、蓝弱视图之间切换；
- 在画面中框选标题、价格、按钮等“必须看清”的区域；
- 用 A / B 两点取色，测量当前颜色对的对比度；
- 提示主色中可能在色觉模拟下相互接近的色对；
- 导出带标记的当前视图 PNG；
- 导出本地 JSON 预检记录；
- 所有图像处理只发生在浏览器内。

## 怎样运行

最简单的方式：

## 它解决的具体问题

普通的色卡工具要求你先知道“哪两个颜色要测”；普通的色盲模拟器也通常只给出一张滤镜后的图。Sightline 的工作流是从最终导出的视觉成品开始：

1. 把真正要发出去的图放进去；
2. 圈出标题、价格、CTA、表单错误提示等关键信息；
3. 在不同阅读情境下观察它们；
4. 对可疑文字和背景做一次实际取色；
5. 把结果作为设计交付前的检查记录。

这让它适合设计师，也适合没有 Figma 文件、只有成品截图的协作方。

## 重要边界

- 对比度结果是对所取 A / B 像素的数学计算；渐变、半透明、阴影、照片底图、字体大小和实际设备都会影响最终阅读体验。
- 色觉视图是设计审查用的近似模拟，不是医学诊断。
- Sightline 不是 WCAG、EAA 或任何法规的合规认证工具。
- 真正面向公众的产品仍应结合键盘、屏幕阅读器、真实用户测试和专业审计。

## 为什么做成开源

设计成品经常包含客户资料、尚未发布的活动和内部界面。把它们上传到陌生网站做检查，本身就是额外风险。Sightline 的默认原则是：**图片留在本机，审查逻辑可被查看。**
