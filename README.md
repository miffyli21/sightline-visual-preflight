# Sightline · 视觉成品预检

> 在发布前，确认海报、社媒图和 UI 截图里的关键信息仍然看得清。

Sightline 是一个完全本地运行的浏览器小工具。它不上传图片、不要求登录，也不试图替代正式无障碍审计；它的用途是让设计师、内容创作者和产品团队在交付前多看一眼真实导出的成品。

English: [README.en.md](./README.en.md)

## 第一版能做什么

- 导入 PNG、JPG、WebP 或 GIF 的第一帧；
- 在原图、小屏、灰阶、红弱、绿弱、蓝弱视图之间切换；
- 在画面中框选标题、价格、按钮等“必须看清”的区域；
- 用 A / B 两点取色，测量当前颜色对的对比度；
- 提示主色中可能在色觉模拟下相互接近的色对；
- 导出带标记的当前视图 PNG；
- 导出本地 JSON 预检记录；
- 所有图像处理只发生在浏览器内。

## 怎样运行

最简单的方式：

1. 直接打开上方在线试用链接，或下载/解压这个项目；
2. 双击“打开 Sightline.bat”，或直接用浏览器打开 index.html；
3. 点击“导入成品图”。

它没有安装步骤、没有账号和没有云端服务。

## 它解决的具体问题

普通的色卡工具要求你先知道“哪两个颜色要测”；普通的色盲模拟器也通常只给出一张滤镜后的图。Sightline 的工作流是从最终导出的视觉成品开始：

1. 把真正要发出去的图放进去；
2. 圈出标题、价格、CTA、表单错误提示等关键信息；
3. 在不同阅读情境下观察它们；
4. 对可疑文字和背景做一次实际取色；
5. 把结果作为设计交付前的检查记录。

这让它适合设计师，也适合没有 Figma 文件、只有成品截图的协作方。

## 重要边界

- 对比度结果是对所取 A / B 像素的数学计算；渐变、半透明、阴影、照片底图、字体大小和实际设备都会影响最终阅读体验。
- 色觉视图是设计审查用的近似模拟，不是医学诊断。
- Sightline 不是 WCAG、EAA 或任何法规的合规认证工具。
- 真正面向公众的产品仍应结合键盘、屏幕阅读器、真实用户测试和专业审计。

## 为什么做成开源

设计成品经常包含客户资料、尚未发布的活动和内部界面。把它们上传到陌生网站做检查，本身就是额外风险。Sightline 的默认原则是：**图片留在本机，审查逻辑可被查看。**

## 开发

这是一个无构建、无依赖的静态网页项目：

~~~text
index.html
styles.css
app.js
~~~

只需编辑文件后刷新浏览器即可。任何贡献都请先阅读 [CONTRIBUTING.md](./CONTRIBUTING.md)；英文贡献说明见 [CONTRIBUTING.en.md](./CONTRIBUTING.en.md)。

## 参与第一轮验证

仓库内的 [validation](./validation) 文件夹包含三张公开测试图和一份五分钟测试脚本。请只用自制、公开或已获许可的素材验证工具；不要把客户视觉稿上传到公开讨论中。

## Alpha 状态

当前版本是 v0.1.0-alpha.2。功能可以使用，但检查逻辑、措辞和导出格式都仍在等待真实工作流反馈。欢迎报告误导性提示、难理解的步骤和隐私问题；不要把工具的结果当作正式合规结论。
