# Contributing to Sightline

Thank you for helping make visual content easier to read.

## Before opening an issue

- Do not upload client work, unreleased products, identity documents, chat logs, or other sensitive images.
- Prefer a public reproduction image, or rebuild the issue with simple color blocks and placeholder copy.
- Include the browser, image dimensions, preview scenario, and steps you took.
- If the issue makes an accessibility claim, include the relevant standard, research, or real-user feedback when possible.

## Good first contribution areas

- Improve the small-screen reading scenario;
- Improve Chinese or English wording;
- Create public test examples for different kinds of visual content;
- Make keyboard operation and screen-reader behaviour clearer;
- Make local preflight records more useful in design review.

## Out of scope

- Marketing Sightline as a compliance certification, medical judgment, or automatic accessibility guarantee;
- Uploading images by default, adding hidden analytics, or adding covert tracking;
- Using client visuals, paid assets, or private screenshots without permission as examples.

## Pull-request principles

1. Keep one pull request focused on one clear problem.
2. Preserve the offline, no-account default experience.
3. Explain any effect on image privacy, performance, or accessibility.
4. If you change calculation logic, include a reproduction and expected result.
